# 第9章 一つの応答をたどる 改訂設計メモ

## 章の狙い

第1章から第8章までの層を再統合し、一要求を観測・仮説・切り分け・検証の流れで追えるようにします。遅延、メモリ、通信、描画、AI品質、変更容易性の問題を、戻るべき層と観測点に対応させます。

## 本文で必ず書くこと

- 9.1の全体像には、分散網とブラウザ描画を追加し、旧構成の7章分だけで終わらないようにします。
- コード、実行、メモリ、通信、アプリケーション、モデル、描画の観測点を一枚の表にします。
- 障害調査は、仮説を立て、観測で反証し、層を移動する進め方として説明します。
- DNS委任・迂回・BGP等の経路障害、画面に出ない・崩れる・遅い描画問題、AI回答品質問題を分けて扱います。
- 最後は送信ボタンへ戻り、読者が全体を一つの出来事として説明できる状態をゴールにします。
