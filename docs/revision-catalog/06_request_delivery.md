# 第6章 要求が届くまで 改訂設計メモ

## 章の狙い

第5章の分散網の上で、アプリケーションの一要求がポート、TCP/UDP/QUIC、TLS、HTTP、キャッシュ、プロキシ、CDNを経てサーバーへ届くまでを説明します。

## 本文で必ず書くこと

- ポート番号とソケットを、同じホスト上の複数プロセスへ通信を届け分ける仕組みとして説明します。
- TCPは接続・順序・再送・フロー制御・輻輳制御をまとめ、パケット損失や待ち行列とつなげます。
- UDPは信頼性を省いた薄い配送であり、QUICがその上に暗号化・多重化・再送等を構成することを概観します。
- TLSは暗号化だけでなく、完全性とサーバー認証を提供することを証明書検証とセットで説明します。
- HTTPはメソッド、ステータス、ヘッダー、ボディを持つアプリケーション層の約束として、各バージョンの違いを過度に深掘りせず位置づけます。
- サーバーの手前にあるキャッシュ、プロキシ、CDN、Service Workerは本文へ昇格し、第8章の描画へ前方参照します。
