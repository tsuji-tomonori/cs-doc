# 執筆規約

本書の本文と演習は、次の規則に従います。
改訂とファクトチェックには、[教材レビュースキル](../skills/cs-textbook-review/SKILL.md)を適用します。
判断の優先順位は「正しさ → 分かりやすさ → やさしい日本語」です。

## 文体

- 本文は、中立的な「です・ます調」で書きます。
- 説明では「〜します」を使い、演習の指示では「〜してください」を使います。
- 一文では、新しい用語を一つだけ定義します。
- 一文一義を守り、一段落では一つの主題だけを扱います。
- 肯定文を基本にします。意味や保証範囲に必要な否定は残します。
- 接続詞は必要な箇所へ絞り、同じ節での重複を見直します。
- 制作指示、自己評価、組版方針などのメタ的な説明は作業記録へ置きます。
- 90文字を超える文は、列挙と定義を分けられないか確認します。
- 「することができます」や「見ていきます」のような冗長な表現は使いません。
- 修辞疑問と「〜のです」は、必要な箇所だけで使います。

## 用語

- 用語は、必要になる順に説明します。
- 定義する用語は `\term{用語}` で太字にし、索引へ登録します。
- 同じ文で複数の用語を定義しません。
- ラベル付き段落では、ラベルと同じ用語を最初に説明します。
- 略語は、正式名称、役割、本書での使い方の順で説明します。
- 「はじめに」は全体の地図に徹し、技術用語の詳しい定義は担当章へ委ねます。

## 表記

- 本文、数式、コードでは半角アラビア数字を使います。
- コード、コマンド、識別子は等幅書体で示します。
- 外部資料から図表を転載せず、必要な図は本書用に作成します。

## 根拠と構成

- 各章は、到達目標、本文、演習、章末の要点を持ちます。
- 各節は、カタログで定めた役割を満たします。
- 節末では、根拠となる仕様、標準、大学資料、研究論文を示します。
- 比喩には適用範囲を添え、仕様、実装、観測結果、教材上の簡略化を区別します。
- 新しい章でも、一つの要求を物理から画面まで追う物語線を維持します。

## 図表と検証

- 動作を解説するアルゴリズムには、入力、途中状態、出力を追える図を添えます。
- 図、数式、コードの数値と処理順を照合します。
- 表は比較軸と前提をそろえます。文字が小さい場合は、情報量や構成を見直します。
- 最終PDFで、図表の文字、改行、はみ出し、改ページを目視します。
- 出典の登録と主張の照合を区別し、確認日、根拠の該当箇所、検証結果を作業記録へ残します。
