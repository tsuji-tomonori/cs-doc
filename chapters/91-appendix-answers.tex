\chapter{付録B　「手を動かす」の解答例と期待出力}

\section{解答例の使い方}

\term{解答例}は、唯一の正解ではなく、入力、処理、出力を照合するための一例です。
コードの版、OS、CPU、時刻、通信先によって変わる値は、完全一致ではなく判定条件を示します。
答えを写すだけでなく、「何を観測し、どの結果なら説明が成り立つか」を自分の記録へ添えてください。

\section{第2章：式を木にする}

次は、本文のASTへ実行部分とエラー処理を加えた全体例です。

\begin{lstlisting}[language=Go,basicstyle=\ttfamily\fontsize{7.0}{8.3}\selectfont]
package main

import (
    "errors"
    "fmt"
)

type Node struct {
    Op          string
    Value       int
    Left, Right *Node
}

func Eval(n *Node) (int, error) {
    if n == nil { return 0, errors.New("missing node") }
    if n.Op == "" { return n.Value, nil }
    l, err := Eval(n.Left)
    if err != nil { return 0, err }
    r, err := Eval(n.Right)
    if err != nil { return 0, err }
    switch n.Op {
    case "+": return l + r, nil
    case "-": return l - r, nil
    case "*": return l * r, nil
    case "/":
        if r == 0 { return 0, errors.New("division by zero") }
        return l / r, nil
    default:
        return 0, fmt.Errorf("unknown operator %q", n.Op)
    }
}

func number(v int) *Node { return &Node{Value: v} }

func main() {
    ast := &Node{Op: "*",
        Left: &Node{Op: "-", Left: number(8), Right: number(2)},
        Right: &Node{Op: "+", Left: number(3), Right: number(1)}}
    value, err := Eval(ast)
    fmt.Println("value:", value, "error:", err)
    _, err = Eval(&Node{Op: "/", Left: number(1), Right: number(0)})
    fmt.Println("division:", err)
    _, err = Eval(&Node{Op: "%", Left: number(5), Right: number(2)})
    fmt.Println("operator:", err)
}
\end{lstlisting}

\begin{lstlisting}[language=bash]
$ go run ast.go
value: 24 error: <nil>
division: division by zero
operator: unknown operator "%"
\end{lstlisting}

葉の値を先に求めてから親の演算へ戻るため、評価順序は後順走査です。
0除算と未知演算子を戻り値で報告でき、呼び出し側が失敗を処理できれば追加課題も達成です。

\section{第3章：置き方と速さ}

本文の二つの関数を\code{lookup\_test.go}へ保存し、先頭へ次を加えます。

\begin{lstlisting}[language=Go]
package lookup

import "testing"
\end{lstlisting}

同じ端末で次を5回実行します。

\begin{lstlisting}[language=bash]
go test -bench=. -benchmem -count=5
\end{lstlisting}

代表的な出力の形は次のとおりです。数値の完全一致は求めません。

\begin{lstlisting}[language=bash]
BenchmarkSliceIndex-8  1000000000  0.8 ns/op  0 B/op  0 allocs/op
BenchmarkMapLookup-8    100000000  12.4 ns/op  0 B/op  0 allocs/op
\end{lstlisting}

判定では、CPU、Go版、要素数、キー分布、事前確保を同じにします。
5回の中央値を比べ、配列の添字アクセスとハッシュ表の検索では定数係数が異なることを説明します。
一方の測定だけから、すべての入力で必ず速いとは結論しません。

追加課題では、\code{make([]int, 0)}と\code{make([]int, 0, n)}を分けてベンチマークします。
事前容量を与えた方で\code{allocs/op}と\code{B/op}が減ることを確かめれば達成です。

\section{第5章：DNSと経路}

\code{dig +trace example.com}では、応答の中に次の順序が現れます。

\begin{enumerate}
  \item ルートのNS情報が次の問い合わせ先を示します。
  \item \code{com.}の権威DNSが\code{example.com.}の委任先を示します。
  \item \code{example.com.}の権威DNSが最終的なレコードを返します。
\end{enumerate}

サーバー名、IPアドレス、TTLは時点や場所で変わるため、順序と役割を判定します。
途中でタイムアウトしても、最後に応答した段階、時刻、利用したリゾルバを記録できれば観測は有効です。

\code{traceroute example.com}の各行はTTLを一つ増やした試行に対応します。
\code{*}は、その試行への応答を観測できなかったことを意味します。
\code{*}の先で宛先が応答する場合もあるため、途中の\code{*}だけで通信断とは判定しません。

\section{第6章：通信時間}

本文の\code{curl -w}は、次のような1行を返します。

\begin{lstlisting}[language=bash]
dns=0.012 connect=0.031 tls=0.084 ttfb=0.142 total=0.143
\end{lstlisting}

各値は開始時点からの累積時刻です。
通常は\code{dns <= connect <= tls <= ttfb <= total}の順になります。
段階の所要時間を求めるときは、隣り合う値の差を取ります。
たとえば上の例では、接続後からTLS完了までがおよそ0.053秒です。

最低5回測定し、時刻、URL、プロキシの有無、HTTP版を残します。
最初の1回だけが遅い場合は、DNS、接続、TLS、キャッシュのどこに差が出たかを比べます。
一つの段階だけを見て全体遅延の原因を断定しないことが判定条件です。

\section{第7章：学習と汎化}

本文のデータ生成と乱数シードを変えずに実行すると、次の値になります。

\begin{lstlisting}[language=bash]
0 0.559948 0.520170
1 0.322496 0.195771
3 0.039028 0.011542
9 0.005280 0.029639
\end{lstlisting}

次数0は訓練データにも十分合わず、過少適合の例です。
次数3は訓練MSEとテストMSEがともに小さいため、この比較では最もよく汎化しています。
次数9は訓練MSEがさらに下がる一方、テストMSEが増えるため、過学習の兆候があります。

Ridge回帰では、次数と正則化係数を訓練データだけで決めません。
訓練、検証、テストへ分け、検証MSEで係数を選んだ後にテストMSEを一度だけ確認できれば達成です。

\section{根拠資料を追うための語}

\term{DOI}はDigital Object Identifierの略で、論文などの対象を持続的に識別する文字列です。
\term{RFC}は、インターネット技術の仕様や知見を公開する文書系列です。
\term{標準仕様}は、複数の実装が共有する要件や意味を定めた文書です。
\term{ライセンス}は、著作物やソフトウェアを利用、変更、再配布できる条件を示します。
本文の説明を確かめるときは、まず仕様、言語リファレンス、標準化団体の資料を開き、版と参照日を記録してください。
