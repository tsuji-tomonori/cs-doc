\chapter{コードから命令へ}
\label{chap:language}

\begin{chapterabstract}
前章で、CPUがビット列を命令として読み、回路の状態を変えるところまで来ました。しかし、AIアプリの開発者が書いたのは長い0と1の列ではなく、処理へ名前を付けて再利用する関数や、値の種類と許される操作を表す型を持つソースコードです。ソースコードとは、人が読み書きしやすいプログラミング言語で記した、変換前のプログラムです。その記述が、どうして回路を動かせるのでしょうか。

ここではCPUが理解できる操作を定めた命令セットから出発し、CPUが直接読む機械語、命令へ人向けの短い名前を付けたアセンブリ言語、さらに人の意図へ近づけた高級言語へ視点を上げます。次に向きを変え、ソースコードが意味のある最小単位、入れ子の構造、機械命令へ姿を変える道をたどります。各段階の名前は、そこへ到着したときに説明します。
\end{chapterabstract}

\begin{learninggoals}
  \item 命令セット、機械語、アセンブリ、高級言語の関係を説明できます。
  \item ソースコードをトークン列とASTへ変換する段階を説明できます。
  \item 木の走査順とAST評価の順序を対応づけられます。
\end{learninggoals}

\section{命令セット}
\label{sec:02-language-01}

CPUは、決められた形式のビット列を命令として解釈します。どの並びを加算と読み、どのレジスタを使い、失敗時に何が起きるかについて、CPUとソフトウェアは共通の約束を持ちます。CPUが理解できる命令の種類と、その使い方をまとめた約束が\term{命令セット}です。

\begingroup
\begingroup
\paragraph{命令セットアーキテクチャ}
        \term{命令セットアーキテクチャ}は、CPUとソフトウェアの間にある命令の約束です。Instruction Set Architectureを略して\term{ISA}と呼びます。architectureはここでは、外から見える全体の構成と約束を意味します。ISAは、利用できる命令、ソフトウェアから見えるレジスタ、扱える値の種類、メモリ位置の指定方法、通常どおり続けられない出来事への対応を定めます。この特別な出来事を\term{例外}といいます。
        CPUはISAの動作を実装します。

\paragraph{命令形式}
        命令を表すビット列の区切り方と各部分の意味が\term{命令形式}です。区切られた一部分を\term{フィールド}といいます。どの操作を行うかを示すフィールドが\term{オペコード}で、operation codeを縮めた名前です。操作対象を示すオペランドには、レジスタ番号や、命令の中へ値そのものを書いた\term{即値}などを配置します。

\par
\endgroup
\medskip
\begingroup
      \centering
    \inlineimage{generated/02-diagram-01.png}
      \vspace{4mm}
\paragraph{ISAと実装}
        ISAという約束を、内部でどの回路構成によって実現するかを\term{マイクロアーキテクチャ}といいます。同じ命令セットを実行するCPUでも、前章で見たパイプラインやキャッシュ、複数の処理を同時に進める並列実行の方式は異なり得ます。
        プログラムはISAが保証する動作へ依存します。

\par
\endgroup
\par
\endgroup


\section{機械語とアセンブリ言語}
\label{sec:02-language-02}

命令セットという約束は、最終的にはメモリ上のビット列として表されます。人が送信処理を書くときは、読みやすい表記が役立ちます。まず命令へ短い名前を付け、同じ動きを読める形にします。

\begingroup
\begingroup
\paragraph{機械語}
        ISAの命令を、CPUが直接解釈できるビット列で表したものが\term{機械語}です。
        どこからどこまでが一命令かという命令境界や、各フィールドの意味を知るには、ISAの仕様と照合する必要があります。

\paragraph{アセンブリ言語}
        機械語の各命令へ、人が覚えやすい短い名前と記号を対応させた言語が\term{アセンブリ言語}です。ADDやLOADのような命令の短い名前を\term{ニーモニック}といいます。
        アセンブリ言語で書いた文字列を機械語へ変換するプログラムが\term{アセンブラ}です。一つの命令がほぼ一つの機械命令へ対応するため、CPUの動きが近くに見えます。

\par
\endgroup
\medskip
\begingroup
\paragraph{代表的な命令の役割}
        \term{ロード}はメモリからレジスタへ値を読みます。\term{ストア}はレジスタからメモリへ値を書きます。
        \term{演算命令}はレジスタ値をALUで処理します。\term{分岐命令}は条件に応じて次に実行する命令の位置、すなわちPCを変更します。

\paragraph{ロード／ストア型の例}
        \code{LOAD R1, [R2]}、\code{ADD R3, R1, R4}、\code{STORE [R2], R3} のように、メモリ操作と演算を分けます。

\par
\endgroup
\par
\endgroup


\section{高級言語}
\label{sec:02-language-03}

命令へ名前を付けても、開発者はレジスタの再利用や分岐先のアドレスを管理し続けなければなりません。AIアプリで表したいのは「入力を検証する」「注文を探す」という意図です。機械の個別の命令より、人が考える処理へ近い書き方を提供する言語が\term{高級言語}です。ここで「高級」は、物理的な回路から見て抽象化の段が高いという意味です。

\begingroup
\begingroup
\paragraph{名前と型}
        値へ付けた名前が\term{変数}です。まとまった処理へ名前を付け、必要な値を渡して呼び出せる形にしたものが\term{関数}です。複数の関連する値を一つへまとめる型を\term{構造体}といいます。\term{型}は、値が数、文字列、注文情報などのどの種類で、どの操作を許すかを表す約束です。高級言語では、アドレスやレジスタ番号の代わりに、これらの名前で意図を表します。

\par
\endgroup
\medskip
\begingroup
\paragraph{制御構造}
        プログラムをどの順序で進めるかを表す書き方が\term{制御構造}です。条件によって道を選ぶ条件分岐、同じ処理を繰り返す反復、例外が起きたとき別の処理へ移る例外処理などを、まとまりの見える構文として記述します。

\par
\endgroup
\medskip
\begingroup
\paragraph{移植性}
        同じソースコードを異なるCPUやOSでも使える性質を\term{移植性}といいます。言語を解析・変換・実行するプログラム一式である\term{言語処理系}が環境ごとの差を吸収できる範囲では、一つのソースコードを複数環境へ移せます。

\par
\endgroup
  \vspace{4mm}
\paragraph{抽象化の対価}
    実行される命令や、メモリ上に置き場所を作る処理は、ソースコードから見えにくくなります。配列などで許された範囲を越えていないか調べる境界検査も同様です。実行時の値の種類に応じて呼び出す処理を選ぶ動的ディスパッチも隠れます。\term{ディスパッチ}は、複数の候補から実際に仕事を任せる先を選ぶことです。
    性能や障害を調べるときは、処理系が抽象化をどう実装するかを確認します。

\par
\endgroup


\section{コンパイル}
\label{sec:02-language-04}

CPUが実行できる形へつなぐため、ソースコードの意味を保ちながら表現を変換します。変換先には機械語や中間表現、別の高級言語があります。この翻訳を\term{コンパイル}といいます。翻訳するプログラムを\term{コンパイラ}といいます。

\begingroup
  \centering
  \inlineimage{generated/02-diagram-02.png}
  \vspace{5mm}
\begingroup
\paragraph{コンパイル}
        コンパイラはソースコードを読み、文法や型を確かめ、段階的に別の表現へ変換します。変換の途中で使う、特定のソース言語やCPUから少し距離を置いた表現が\term{中間表現}です。中間表現にすると、同じ形のまま最適化したり、複数のCPU向け命令へ変換したりしやすくなります。

        実際のCPUがそのまま実行する機械語を\term{ネイティブ機械語}といいます。一方、ソフトウェアで作った仮想的な機械向けの命令列を\term{バイトコード}と呼ぶことがあります。

\par
\endgroup
\medskip
\begingroup
\paragraph{リンクとロード}
        一つのプログラムを複数のソースファイルへ分けると、あるファイルから別の関数名を参照します。各ソースを変換して得た機械語と補助情報のファイルが\term{オブジェクトファイル}です。複数のオブジェクトファイルとライブラリを結び、名前が実際のどの位置を指すか決める処理が\term{リンク}です。リンクを行うプログラムが\term{リンカ}です。

        リンク後に得られ、OSが起動できる形のファイルを\term{実行可能ファイル}といいます。それをメモリ上へ配置して実行の準備をするOSの機能が\term{ローダー}です。次章で、実行中のプログラムであるプロセスと、そのメモリの見え方であるアドレス空間を詳しくたどります。

\par
\endgroup
  \source{Cornell CS4120, “Introduction to Compilers”}
\par
\endgroup


\section{実行方式}
\label{sec:02-language-05}

ソースから命令へ至る方法には、いくつかの組み合わせがあります。事前に機械語へ変える処理もあれば、実行しながら解釈したり、途中の表現を仮想機械で動かしたりする処理もあります。違いは、翻訳する時点と、翻訳を担う仕組みにあります。

\begingroup
\begingroup
\paragraph{インタプリタ}
        ソースコードや中間表現を読み、その意味に対応する処理を進めるプログラムが\term{インタプリタ}です。実行前に全体をネイティブ機械語へ変換するとは限らず、読みながら実行できます。
        一行ずつ入力して結果を見る対話的な実行や、実行中に型や処理を変える機能を作りやすい一方、命令をその都度読み解く時間が加わります。

\paragraph{仮想機械}
        実在するCPUの代わりとなる命令やメモリの規則をソフトウェアで実現したものが\term{仮想機械}です。英語のVirtual Machineを略してVMとも呼びます。コンパイラがバイトコードへ変換し、仮想機械がそれを解釈する、または実行中に機械語へ変換します。

\par
\endgroup
\medskip
\begingroup
\paragraph{JITコンパイル}
        \term{JITコンパイル}のJITはJust In Time、すなわち「必要になった時点で」を意味します。実行中に、頻繁に通るコードなどを機械語へ変換します。
        同じ結果を保ちながら、実行時間や使用メモリなどを改善する変換を\term{最適化}といいます。JIT方式では、実際によく使われた型や経路などの実行時情報を最適化へ利用できます。

\paragraph{分類より変換経路を見る}
        実際の実行方法は、コンパイルと解釈をどの段階で行うかで説明できます。
        どの表現を、いつ、何へ変換するかを確認します。

\par
\endgroup
\par
\endgroup


\section{字句解析}
\label{sec:02-language-06}

翻訳の入口にあるのは、ただの文字列です。コンパイラは、文字の連なりを名前、数値、記号といった最小のまとまりへ切り分けます。この処理を\term{字句解析}といいます。「字句」は、文字から作られた意味のある最小の単位を指します。利用者の入力をアプリが解析するときにも似た境界が現れます。

\begingroup
\noindent{\sffamily\bfseries\color{MutedBlue}入力例：\code{total = price * 110 / 100}}\par\medskip
  \centering
  \inlineimage{generated/02-diagram-03.png}
  \vspace{6mm}
\begingroup
\paragraph{トークン}
        字句解析で切り出した一単位が\term{トークン}です。たとえば\code{total}は、名前を表す\term{識別子}です。\code{=}や\code{*}は、操作を表す\term{演算子}です。\code{110}は整数という種別です。トークンは「識別子」という種別と「total」という値のような組で表します。

        人向けの説明としてコードへ書く\term{コメント}や、トークンの区切りにしか使わない空白は、後続処理に不要なら除外できます。ただし、元の何文字目にあったかという位置情報は、エラー箇所を示すために保持できます。

\par
\endgroup
\medskip
\begingroup
\paragraph{字句エラー}
        言語の規則に合うトークンを作れないことが\term{字句エラー}です。たとえば引用符で囲んでコード中に直接書いた文字列を\term{文字列リテラル}といい、閉じる引用符がなければ一つのトークンをどこまで読めばよいか決まりません。

\par
\endgroup
\par
\endgroup


\section{構文解析}
\label{sec:02-language-07}

トークンへ分けただけでは、どの演算を先に行い、どの名前がどの値に結び付くかは分かりません。トークンの並びが言語の組み立て規則へ合うか確かめ、平らな列の背後にある入れ子構造を取り出す処理が\term{構文解析}です。構文解析を行うプログラムを\term{パーサー}といいます。

\begingroup
\begingroup
\paragraph{文法の例}
        トークンをどの順序とまとまりで並べられるかを定めた規則が\term{文法}です。「左側のまとまりを、右側のどの形として作れるか」を示す規則を\term{生成規則}といいます。加算と乗算を含む式の文法は、例えば次のように記述できます。
        \[
        \begin{aligned}
          \mathit{expr} &\rightarrow \mathit{expr}+\mathit{term}\mid\mathit{term}\\
          \mathit{term} &\rightarrow \mathit{term}*\mathit{factor}\mid\mathit{factor}\\
          \mathit{factor} &\rightarrow \mathrm{INT}\mid(\mathit{expr})
        \end{aligned}
        \]
        $\mathit{expr}$、$\mathit{term}$、$\mathit{factor}$は、それぞれ式、項、因子という途中のまとまりにつけた名前です。矢印は「左側を右側の形へ展開できる」、縦線$\mid$は「いずれかを選べる」という意味です。INTは整数トークンを表します。この規則は、乗算を加算より内側のまとまりに置くことで、演算子の優先順位と括弧の対応を表します。

\par
\endgroup
\medskip
\begingroup
\paragraph{パーサーの出力}
        パーサーはトークン列を文法規則へ対応づけ、どの規則をどの順に使ったかを枝分かれで表す\term{構文木}、または次節の抽象構文木を構築します。

\paragraph{構文エラー}
        期待するトークンと実際のトークンが一致せず、文法に沿った構造を作れないことが\term{構文エラー}です。
        例えば、\code{1 + * 2} は右辺の項が欠けています。

\par
\endgroup
  \source{Stanford CS143, “Abstract Syntax Trees”}
\par
\endgroup


\section{抽象構文木}
\label{sec:02-language-08}

文法どおりの構文木には、括弧や区切り記号など翻訳後には不要な情報も含まれます。必要な演算と関係だけを枝分かれの形へ残したものが\term{抽象構文木}です。英語のAbstract Syntax Treeを略して\term{AST}と呼びます。後続処理はASTを使い、「左を計算してから右を計算する」といった依存を直接たどれます。

\begingroup
\begingroup
\paragraph{構文木との違い}
        構文木は文法規則の展開を詳しく表します。
        ASTは括弧や、式や項など文法を組み立てる途中の名前を省き、演算とオペランドの関係を残します。

\paragraph{用途}
        AST上の一つの要素を\term{ノード}といいます。型の規則へ合うか確かめる処理が\term{型検査}です。実行結果を変えず処理を改善する操作が最適化です。低い表現や命令を作る処理が\term{コード生成}です。実行せずに問題を調べる処理が\term{静的解析}です。これらの処理は、ASTのノードを順に扱います。

\par
\endgroup
\medskip
\begingroup
      \centering
      \inlineimage{generated/02-diagram-04.png}
      \vspace{4mm}
\paragraph{式の構造}
        \code{1 + 2 * 3} では、乗算ノードが加算ノードの下へつながる子になるため、乗算を先に評価します。ここで\term{評価}とは、式の規則に従って最終的な値を求めることです。

\par
\endgroup
  \source{Stanford CS143, “Abstract Syntax Trees”}
\par
\endgroup


\section{木構造}
\label{sec:02-language-09}

ASTを理解するには、個々の演算より先に、\term{木構造}という形そのものを読む必要があります。木構造は、一つの始点から枝分かれし、枝の先がさらに枝分かれする形です。一本の輪を作らず、二つの要素の間をたどる道は一通りです。構文だけでなく、画面上の部品、フォルダ、依存関係にも現れます。

\begingroup
\begingroup
\paragraph{構成要素}
        木で、親を持たない始点を\term{根}といいます。値とほかのノードへの関係を持つ要素を\term{節点}といいます。下へつながる子を持たない節点を\term{葉}といいます。ASTの説明で使ったノードと節点は同じものです。
        節点どうしを結ぶ線を\term{辺}といいます。ある節点の一段上を\term{親}といいます。一段下を\term{子}といいます。

\paragraph{再帰的な定義}
        一つの節点と、その下のすべての節点を合わせた小さな木を\term{部分木}といいます。木全体は、一つの根と0個以上の部分木から構成されます。このように、あるものを同じ種類のより小さなものを使って定めることを\term{再帰的な定義}といいます。

\par
\endgroup

\section{再帰とコールスタック}
\label{sec:02-language-10}

木の\term{深さ}とは、根から最も遠い葉までにいくつの辺を通るかという大きさです。深さは入力ごとに変わるため、すべての段を決まった回数の繰り返しだけで書くのは不自然です。「部分木を同じ方法で処理する」と定義し、関数が自分自身を呼び出す方法を\term{再帰}といいます。形が一段小さくなるたびに同じ関数へ仕事を渡せます。その途中経過を現実に保持する場所がコールスタックです。

\begingroup
\begingroup
\paragraph{二つの構成要素}
        これ以上小さくせず、その場で答えを返して再帰を止める条件が\term{基底条件}です。
        問題を小さくして同じ関数を呼ぶ部分が\term{再帰ステップ}です。
        基底条件と再帰ステップをそろえ、問題が小さくなることを確認します。

\paragraph{コールスタック}
        関数を呼び出した順に途中状態を積み、最後に呼んだ関数から先に完了させる記憶領域が\term{コールスタック}です。関数へ渡した値である引数、その呼び出しの中だけで使う局所変数、完了後に戻る命令位置を、一回の呼び出しごとのまとまりとして保持します。このまとまりを\term{スタックフレーム}といいます。
        深すぎる再帰で用意された領域を使い切ることを\term{スタックオーバーフロー}といいます。

\par
\endgroup

\section{深さ優先探索}
\label{sec:02-language-11}

入力から結果を求めるための、有限の手順を定めたものが\term{アルゴリズム}です。
木を訪問する順序は、処理の目的に合わせて選びます。データ構造の要素を規則に沿って順番に調べることを\term{探索}といいます。一本の枝を行けるところまで奥へ進み、行き止まりで一つ戻る方法が\term{深さ優先探索}です。英語のDepth-First Searchを略して\term{DFS}と呼びます。式の値を求めるには親の演算より先に子の結果が必要なので、この順序が合います。

\begingroup
\begingroup
\paragraph{三つの走査順}
        木の各節点を一度ずつ訪れることを\term{走査}といいます。ここでは、各節点が左と右に最大一つずつ子を持つ二分木を扱います。\term{前順}は、節点、左部分木、右部分木の順に訪問します。\term{間順}は、左部分木、節点、右部分木の順に訪問します。
        \term{後順}では左部分木と右部分木を訪れてから節点を処理します。名前の「前」「間」「後」は、親の節点を子に対していつ処理するかを示します。

\paragraph{再帰による実装}
        関数呼び出しのスタックが、訪問途中の節を保持します。
        木の定義と同じ構造で記述できます。

\par
\endgroup
\medskip
\begingroup
\paragraph{明示的なスタック}
        後から取り出す値を順に積み、最後に入れた値から先に取り出すデータ構造も\term{スタック}と呼びます。コールスタックと同じ「後入れ先出し」の規則です。再帰を使わず、次に訪問する節点をこのスタックへ自分で積む方法が\term{明示的なスタック}です。
        訪問順を保つには、子を積む順序に注意します。

\paragraph{必要な記憶量}
        子を一つずつ再帰でたどる実装では、木の深さに比例する途中状態を保持します。すべての子を一度に積む実装では、子の数も必要な記憶量へ影響します。
        節点と辺で対象同士のつながりを表す構造を\term{グラフ}といいます。木と違って輪になった経路を持てるため、同じ節点を回り続けないよう、一度訪問した節点を記録する集合も必要です。\term{集合}は、同じ値を重複させずに所属を管理するデータ構造です。

\par
\endgroup
  \source{Stanford CS106B, DFS / Backtracking lecture}
\par
\endgroup


\section{ASTの評価}
\label{sec:02-language-12}

ここで木の走査を、実際の計算へ戻します。葉の数値を受け取り、親の演算へ渡し、その結果をさらに上へ返すと、平らだったソースコードが一つの値になります。章の冒頭で見た命令列は、この意味を下位の操作へ写したものです。

\begingroup
  \centering
  \inlineimage{generated/02-diagram-07.png}
  \vspace{4mm}
\begingroup
\paragraph{評価順}
        葉の1、2、3を読み、2と3を乗算して6を得ます。
        最後に1と6を加えて7を得ます。

\par
\endgroup
\medskip
\begingroup
\paragraph{コード生成との関係}
        この四則演算のASTから命令を作る場合も、子の結果を先に用意してから親の演算を作ります。そのため、後順走査に近い構造になります。条件分岐や、条件によって右辺の評価を省く演算では、言語が定める評価条件も反映します。

\par
\endgroup

\endgroup


\section{幅優先探索}
\label{sec:02-language-13}

始点からの近さを優先したい場合もあります。最も浅い位置を探したいときや、始点から同じ距離にある候補を順番に調べたいときは、近い節点から層状に進む方が自然です。この方法が\term{幅優先探索}です。英語のBreadth-First Searchを略して\term{BFS}と呼びます。途中状態を保つ道具もスタックからキューへ変わります。

\begingroup
\begingroup
\paragraph{キューによる探索}
        入れた順に値を並べ、最初に入れた値から取り出すデータ構造が\term{キュー}です。待ち行列と同じ「先入れ先出し」の規則です。
        始点をキューへ入れ、登録済みとして記録します。先頭を取り出し、隣の節点を調べます。未登録の節点は末尾へ入れ、その場で登録済みにします。この操作をキューが空になるまで繰り返します。

\paragraph{性質}
        辺を通る費用や距離を\term{重み}といいます。辺の重みがすべて同じ正の値であるグラフでは、BFSは始点から通る辺の数が最も少ない\term{最短経路}を求められます。同じ距離の節点をすべて調べてから次の距離へ進むためです。

\par
\endgroup
\medskip
\begingroup
\paragraph{DFSとの使い分け}
        DFSとBFSは、保持するデータ構造と訪問順、向いている用途が異なります。
        \begin{tabularx}{\linewidth}{@{}lYY@{}}
          \toprule
          & DFS & BFS\\
          \midrule
          保持 & スタック & キュー\\
          順序 & 深さ優先 & 距離順\\
          例 & AST評価 & 最短辺数\\
          \bottomrule
        \end{tabularx}

\paragraph{ASTではどう使うか}
        式の評価は依存関係に合うDFSが自然です。
        BFSは、深さ別の表示や最浅の条件探索などに使えます。

\par
\endgroup
  \source{Stanford CS106B, Graphs / BFS lecture}
\par
\endgroup


図\ref{fig:02-dfs-bfs}では、子を左から調べます。
DFSの前順はA、B、D、E、Cの順です。
BFSはAを取り出した後、BとCをキューへ入れます。
Bを取り出すと、Cの後ろへDとEを追加します。
登録時に印を付けると、同じ節点を重ねてキューへ入れることを防げます。

\section{手を動かす：式を木にする}
\label{sec:02-language-14}

短い式を木として組み立て、葉から根へ値が戻る過程をコードで確かめます。この小さな翻訳器は、送信処理を含む大きなプログラムが命令へ変わる仕組みの縮図です。

\begingroup
\begingroup
      \begin{lstlisting}[language=Go]
type Node struct {
    Op          string
    Value       int
    Left, Right *Node
}

func Eval(n *Node) int {
    if n.Op == "" { return n.Value }
    l, r := Eval(n.Left), Eval(n.Right)
    switch n.Op {
    case "+": return l + r
    case "-": return l - r
    case "*": return l * r
    case "/": return l / r
    }
    panic("unknown operator")
}
      \end{lstlisting}
\par
\endgroup
\medskip
\begingroup
\paragraph{作るAST}
        \code{(8 - 2) * (3 + 1)} を表す節を組み立てます。
        \code{Eval}の結果が24になることを確認します。

\paragraph{追加課題}
        0除算の検査と、未知の演算子を返り値で報告する設計を追加してください。

\par
\endgroup
\par
\endgroup


\section{プロセスへ}
\label{sec:02-language-15}

開発者のコードは、文字列からトークンへ、トークンからASTへ、ASTからより低い表現へ変わり、命令セットが定める機械語へ到着しました。途中の木構造は、依存する部分を先に処理する順序を与え、再帰とスタックがその歩みを支えます。

これでCPUが読めるファイルは用意できました。しかし、ファイルは自分でCPU時間を取り、入力文を置くメモリを確保できません。次章ではOSがこの命令列へ実行の場を与え、保存されたプログラムが動いているプロセスになる瞬間を追います。

\takeaway{言語処理は、意味を確かめながら表現を少しずつ変え、機械が実行する命令へつなぐ処理です。}


\section{旅をたどり直す}
\label{sec:02-language-16}

送信処理のソースコードを一行思い浮かべ、それがCPUの命令になるまでを逆向きにも順向きにもたどってください。次の問いでは、各表現が誰に読みやすく、何を次へ渡すかを言葉にします。

\begingroup
  \begin{enumerate}
    \item ISAとCPUのマイクロアーキテクチャは、何をそれぞれ定めますか。
    \item ロード、ストア、分岐は、レジスタ、メモリ、PCをどう変更しますか。
    \item コンパイラとインタプリタを単純な二分類にできない例を示してください。
    \item \code{x = 12 + y} をトークンへ分け、各トークンの種別を示してください。
    \item 構文木とASTで保持する情報は、どのように異なりますか。
    \item AST評価に後順走査が適する理由を説明してください。
    \item 重みなしグラフの最短経路にBFSを使える理由を説明してください。
  \end{enumerate}
\par
\endgroup
